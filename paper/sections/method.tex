\section{Method}\label{sec:method}

\kanerva{} is built on SQLite, FTS5 and NumPy, and no component calls an LLM. A host agent, when present, writes notes and judges them through tools. The token cost of memory is what the hooks inject, at session start, per prompt and per file, plus the lists a write returns and one short agent turn at the end of a session with real work.

\subsection{Write path}
A write redacts secrets, drops exact duplicates and stores the note with its full-text entry and embedding. A write with a key closes the live note with that key, which stays as history. Most notes have no key, and only an agent can tell that a new note replaces an older one, so \texttt{memory\_remember} returns up to five similar notes, taken in turn from word matches and close vectors. A hint tells the agent to retire a note that only held the old value, or to edit out the outdated part of a longer one. The store lists and the agent decides.

\subsection{Read path}
Candidates are the top 200 lexical and dense hits and, with vectors, the notes written next to the 50 best hits in the same session, since a conversation often splits one fact across adjacent turns.

\paragraph{Relevance.} Each candidate gets a probability of being needed from gradient-boosted trees over 29 features: retrieval ranks and scores, the note's length and content, query--note overlap, role and speaker, neighbouring turns, recency, and ACT-R activation \cite{anderson2004integrated}. The trees are fitted on LongMemEval-S, LoCoMo, BEAM-1M and 34 RepoMem repositories, with conversations and code at equal weight, and they run on NumPy in tens of milliseconds, so a user trains nothing. Separate models cover the lexical, static-embedding, dense and reranker configurations.

\paragraph{Selection.} The weight of a note combines that probability with validity and a learned lift, and selection maximises the sum of weights \eqref{eq:objective} under the budget (Algorithm~\ref{alg:retrieve}). \textsc{Greedy}$(w,B,\nu)$ goes through candidates in order of $w_m/c(m)^{\nu}$ and keeps each one that still fits. Length enters as a feature and as the cost, so the model can learn that short turns are rarely needed and density does not favour short junk. Coverage and facility-location terms had no measurable effect on development data, so they are off.

\begin{algorithm}[t]
\caption{\textsc{Retrieve}$(q,B,t)$}\label{alg:retrieve}
\begin{algorithmic}[1]
\State $C\gets$ lexical hits $\cup$ dense hits $\cup$ their same-session neighbours
\State Remove superseded notes and those with a newer near-twin, unless $q$ asks for history
\For{$m\in C$}
  \State $p_m\gets$ relevance model on features of $(m,q)$
  \State $\rho_m\gets$ class survival at age $t-\tau^{\mathrm{v}}(m)$, discounted by newer similar facts
  \State $w_m\gets\rho_m\min(1,\ell_m p_m)$ \Comment{$\ell_m$: learned lift}
\EndFor
\State $\mathcal{S}\gets\{\textsc{Greedy}(w,B,\nu):\nu\in\{1,\tfrac12\}\}\cup\{\arg\max_{c(m)\le B}w_m\}$
\State \Return $\arg\max_{S\in\mathcal{S}}F(S)$
\end{algorithmic}
\end{algorithm}

\paragraph{Query gate.} Selection alone fills the budget with the best of a bad lot, so the plugins first ask whether the store can answer the prompt at all. A logistic model over six signals of the result list (four without vectors), fitted to tell a store's own questions from questions drawn from other stores, gives no notes to a prompt below its threshold. Above it, the plugins drop selected notes with weight below $0.02$. Session start is not gated, because its query is generic.

\paragraph{File notes.} The file an agent opens says more about a change than the prompt does. When a session first touches a file, the hook returns live notes that name it, within 150 tokens per file and eight times that per session, leaving out what the prompt brought and files that many notes name. This is a plain lookup with no relevance model.

\subsection{Validity}
Keyed facts have exact version chains: a superseded note leaves the candidates unless the query asks for history. Text without keys falls to the \emph{near-twin rule}: a newer fact nearly identical to an older one removes it. Twins are compared by sentence vectors and by hashed words, because a sentence model hears little difference between \texttt{FOO = 3} and \texttt{FOO = 4}, and stores without vectors use words alone. To keep the rule from firing on neighbouring facts, a twin must cover the query at least as well as the older note and hold as many of its words whole, and a note that says less by more than one word is not a newer version. Only facts replace each other, since two similar events are still two events. Natural-language updates rarely look like twins, so they are left to the agent, through the write path.

Live notes also age, by a Gamma--Poisson hazard estimated per class of fact from the store's own version history. Section~\ref{sec:stale} measures what this adds.

\subsection{Learning from the agent}\label{sec:learning}
The relevance model ships fitted and cannot know how notes behave in one project. Learning rests on a \emph{verdict}: at the end of a session with real work, where the plugin already asks the agent for a short note, it also asks which notes changed what the agent did or saved it work, and which turned out wrong. A session with no verdict teaches nothing, since silence is not evidence. Verdicts are tied to the project, and a note counts once for each injection that showed it, however often it is named.

\paragraph{Lift.} Let $h_m$ count the times a note helped, and let $e_m$ sum the model's probabilities over its injections, plus one each time it misled. A rate $b$ over all notes removes the difference in scale between an agent's marks and the model's probabilities. Evidence on one note is scarce, so it is pooled. Notes fall into groups (test commands, build commands, other keyed facts, edit trails, facts, events), and each level starts from the one above, from a group across projects to a group in project $s$ to the note:
\begin{align*}
\ell_g&=\frac{h_g+\kappa_g}{b\,e_g+\kappa_g},\qquad \ell_{s,g}=\frac{h_{s,g}+\kappa_g\,\ell_g}{b\,e_{s,g}+\kappa_g},\\
\ell_m&=\mathrm{clip}_{[\frac14,4]}\,\frac{h_m+\kappa_m\,\ell_{s,g}}{b\,e_m+\kappa_m},
\end{align*}
with $\kappa_g=10$ and $\kappa_m=1$. With no evidence every level is $1$. A note the agent found by search or beside a file has no injection on record, so it adds to its own $h_m$ alone.

\paragraph{Shadow check.} When learning acts, lift changes nothing until it has shown it ranks better. Before a verdict updates any record, it scores the model's ordering and the learned one on pairs of a note that helped and one that did not. Lift starts once the learned ordering wins two percent more of at least 40 pairs, a verdict adds at most ten pairs, and it stops if the lead goes. A project's own record decides once it has enough pairs, and until then the record across projects.

\paragraph{Gate and floor.} A note the gate or the floor stops is never shown, so waiting yields no evidence about it. In this mode probes start from the first prompt: a quarter of prompts, and a tenth once a project has eight judged sessions, get a wider list even if they fall up to three units below the gate, with notes down to a tenth of the floor. Each setting moves only if it beats the shipped one by two sessions of worth, counting each session once, where a prompt is worth what it helped minus $\frac14$ and a note minus $\frac1{20}$. What only a probe could show is weighted by the inverse of the probe rate. Probing stops in a project where verdicts do not come. The relevance model's weights never change.

\paragraph{Default.} Acting on verdicts did not pass its test (Section~\ref{sec:verdicts}), so the plugins ship with \texttt{KANERVA\_LEARN=shadow}: they ask for verdicts, record them and run the shadow check, and lift and probes change nothing. \texttt{auto} turns them on, and \texttt{0} stops asking.

\subsection{Optional modules}
Three modules are off by default. \emph{Consolidation} summarises clusters of near-duplicates extractively and moves the sources to an archive that \textsc{Expand} restores from, following evidence that irreversible rewriting erodes detail \cite{colaco2026ratedistortion,zhang2025ace}. \emph{Forgetting} archives notes idle for $\tau$ days or beyond a token capacity. \emph{Excerpts} let a long note enter selection as the run of sentences that best covers the query, which adds a constraint that Proposition~\ref{prop:selection} does not cover.
